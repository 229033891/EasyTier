### 2. 修掉一个真实产品 bug：int64 字段导致配置无法保存（BigInt 泄漏）

**症状**：配置里只要有 `managed_credentials` 条目，`toBackendNetworkConfig()` 就抛 `Cannot parse JSON bigint for api.manage.ManagedCredentialConfig#expiry_unix`。

**根因链**：
1. 代码生成用的是 **protobuf-ts**（不是 protobufjs），`int64`/`uint64` 运行时是 **BigInt**（`api_manage.ts` 里只有两个：`instance_recv_bps_limit`、`managed_credentials[].expiry_unix`），而在 **JSON 形状里必须是十进制字符串**。
2. `toBackendNetworkConfig` 走「消息实例 → `prepareNetworkConfigForProtoJson` 展开成普通对象 → 再 `fromJson`」。展开时 BigInt 漏进普通对象，第二次 `fromJson` 就拒绝。
3. `instance_recv_bps_limit` 早就有专门补丁（`normalizeLegacyOptionalUint64` + `normalizeUint64ForInput`），但**嵌套消息里的 int64 没人管**。且 `expiry_unix` 是**非 optional**，protobuf-ts 生成的类会把它初始化成 `0n`，所以**只要 `managed_credentials` 非空就必炸**（不是"设了才炸"）。

**影响面（真实可达）**：`toBackendNetworkConfig` 被 `easytier-web/frontend/src/modules/api.ts`（4 处：保存/校验/启动）和 `easytier-gui/src/composables/backend.ts`（5 处）调用 → 带 managed credentials 的网络在 web 控制台和 GUI 里**保存/启动都会失败**。

**修法**：在 `networkCompat.ts` 的 `dropUnsupportedJsonValues()` 加一行通用转换——`typeof value === 'bigint' → value.toString()`。安全性：该函数只被 `prepareNetworkConfigForProtoJson` 调用，而它的两个调用方（`normalizeNetworkConfig` / `toBackendNetworkConfig`）后面都紧跟 `fromJson`，BigInt 在那里本来就是非法输入（以前直接抛，现在转成它想要的字符串）；且它按树递归，嵌套消息里的 int64 一并覆盖。附带好处：`instance_recv_bps_limit` 从服务器读回是 BigInt 时，以前会被静默丢弃，现在能正确保留。

**回归测试**：`tests/config-ui.spec.ts` 新增 `round-trips int64 fields nested in managed_credentials into backend JSON`（**必须放 vitest**——`test:network-config` 脚本 CI 不跑，`linux.yml:77` 只跑 `test:config-ui`）。

**复验**：`test:config-ui` 13 文件 **79 passed**；`test:network-config` **10/10 ok**（`pnpm test` 两半首次全绿）；`vue-tsc -b` 0 错；`vite build` 成功；`easytier-gui` vue-tsc 0 / eslint 0；`easytier-web/frontend` vue-tsc 0。
