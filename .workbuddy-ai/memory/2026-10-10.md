## 暂存区清理（10:19–10:25）——踩到「周期性自动暂存」

老大让把构建调试残留从暂存区剔出去。做了：
- 4 个 `.tmp-{dns,gui,manager,rpc}.diff` → `restore --staged` + **删磁盘文件** → 彻底消失 ✅（这类 untracked 删除后自动暂存无可 add）
- 20 个删除（`.tmp/**`、`.workbuddy-ai/{proc*.txt,tmp/**}`、`build.log`）→ `restore --staged` 变 ` D`，**但 ~20s 后又被自动 add 回 `D `**

**发现 1（环境，重要）**：本工作区存在**周期性自动 `git add`（约 1 分钟一次）**，证据是 `.git/index` 的 mtime 在我 sleep 期间被改写（10:23:41），且我 unstage 后立即回读是 ` D`、隔 20s 又变 `D `。→ **`git restore --staged` 无法持久生效**。以后要「让某路径不进提交」只有两条路：
  - (a) 让 **worktree == HEAD**：`git checkout HEAD -- <paths>`（或 `git restore --source=HEAD --staged --worktree`）→ 无改动，自动暂存无从下手；
  - (b) 单独 `git commit -- <paths>`（只提交指定路径，绕过 index 里的其他内容）。
  → **教训**：凡 unstage 类操作，回读间隔要 ≥1 分钟才能下结论；只回读一次会误判。

**发现 2（代码，非我改动）**：`easytier-gui/src-tauri/src/lib.rs::should_report_to_config_server` 在我上一轮审查**之后被改成「权威优先」**（`Some(Web)=>true / Some(User)=>false / None=>本地`），不再是「任一侧 Web 即上报」。已重新审查，**无 bug**：
