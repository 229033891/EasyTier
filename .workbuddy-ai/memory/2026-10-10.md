## 修复轮（07:22–07:57）与「并行编辑」教训

老大让修上面提的 5 个小问题，结果**文件在我改的同时被并行编辑 + 自动暂存**，我反复跑验证追一个不断变化的状态 → 老大直接问「你是否陷入循环了?」。**是的，浪费了几轮。**

**信号**：`git diff` 出现「反向」内容（我的新文案出现在 `-` 侧、旧文案在 `+` 侧）→ 说明 worktree 被别的进程写过、而 index 有我的版本。**遇到这种情况应该立刻停下问，不要再跑验证。**

**5 条最终结果**（终态在提交 `0d1e2e4d feat(chips): enhance AutoComplete input handling with focus out and keydown events`）：
1. `chips_placeholder` 文案 → **不该改**：`proxy_cidrs` / `routes` 是 typeahead 字段，新设计里**只绑 keydown、不绑 focusout**（避免点建议项时把半截查询词提交成 chip），共享文案不能承诺「点别处即添加」。原措辞正确。
2. `onChipsBlur` 死导出 → 已删 ✓
3. 两个新测试文件的 UTF-8 BOM → 已剥离 ✓（`dns-host-dirty.spec.ts` 被重写时又带回来一次，已再剥）
4. 脏标记不对称 → 已修：`toBackendNetworkConfig` 里对 `dns_config.hosts` 与 `dns_config.forwarders` 都过滤「全空行」→ 空行不算脏，半填算脏。测试断言已同步。
5. ACL 端口 placeholder `80, 1000-2000` → **误报**：后端每个元素必须是 `u16` 或 `start-end`（`peers.rs::parse_port_list`），单个字符串含逗号会 parse 失败 → 按逗号切成两个 chip **正是**正确行为。

**残留**：`proxy_cidrs` / `routes` 两个 typeahead 字段点别处仍会丢草稿（这是「不误提交」换来的代价，属取舍不是 bug）。PrimeVue 建议项**没有** `mousedown.prevent`，所以点建议项时 input 确实会先 blur —— 若要两者兼得，可在 focusout 里判断焦点是否移入建议浮层，而不是靠 `aria-expanded`。
