## 修复顶栏下方 52px 空白带（已完成）
用户截图指出顶栏与页面标题卡之间存在空白。**实测确认**（无头 Chrome 复刻布局测量）：
- 顶栏 `.top-navbar` 是 `position: sticky`，**已占据文档流**，高度 49px。
- 但 `MainPage.vue` 的 `.et-main-content` / `.et-main-content--mgmt` 又加了 `padding-top: calc(3.25rem + safe-area)` = 52px，属于**重复占位**。
- 对比实测：修复前 nav→header 间距 52px，修复后 0px（header_top 49 == navbar_bottom 49，无重叠）。

修复：两处 `padding-top` 改为 `padding-top: env(safe-area-inset-top, 0px)`。

**方法论教训（重要）**：上一轮我曾仅凭 CSS 推演就宣称「布局保持等价」，结果漏掉了这个空白。正确做法是**用无头 Chrome 复刻布局并实测几何值**：
```
chrome --headless=new --disable-gpu --window-size=W,H --virtual-time-budget=4000 --dump-dom file:///...html
```
在页面里 `getBoundingClientRect()` 输出到 pre#result，用 `grep -A 20 'id="result"'` 取值。此法可快速验证 sticky/fixed、flex 分配等布局问题，无需跑起完整应用。

**待确认**：侧栏 `aside` 是 `fixed top-0` + `pt-14`（56px）为 fixed 元素让位，逻辑正确但 56 vs 实测 49px 有 7px 偏差（非本次范围，未改）。
另外 DeviceManagement 有两根节点（v-if spinner + v-else RemoteManagement），建议改布局后在浏览器实看一眼确认无副作用。

## 关键陷阱：`.fixed` vs `.top-navbar` 优先级
`<nav>` 同时有 Tailwind `fixed` 类和 `.top-navbar{position:sticky}`。二者选择器优先级相同 (0,1,0)，**由样式表顺序决定胜者**。实测构建产物 `dist/assets/index-*.css`：
- `.fixed{position:fixed}` 在偏移 ~908896
- `.top-navbar{position:sticky}` 在偏移 ~939718（更靠后）
→ **sticky 胜出，顶栏占据文档流**。判断此类冲突必须查构建产物的偏移顺序，不能只看源文件或凭印象。
