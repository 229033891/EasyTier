### 发现的问题

**P1（真 bug，已记入 MEMORY.md §12）**：storage-first 打坏 GUI 的 Windows `dev_name` 回写。
`easytier-gui/src-tauri/src/manager.rs::persist_runtime_dev_name`（`#[cfg(windows)]`）依赖 `handle_get_network_config` 返回**运行时配置**（RPC 优先）来读内核分配的 wintun 适配器名；库里那份正是 dev_name 为空的。存储优先后 15 次重试全部拿到空名 → 放弃写入 → Windows 上适配器名不再持久化 → 每次重启可能多一块 `et_*` 网卡（正是该函数当初要修的问题）。修法：给它一条强制 RPC 的路径，或只在 web 侧存储优先。

**P2（语义变化，有数据风险）**：库里有行就永不查设备。设备本地改过、未回写 Web 库的配置，编辑页会显示库里旧版本；用户直接保存可能覆盖设备的新改动。文档只在 Archive §4「已知限制」里标了，建议在 Current 文档（`desktop-gui-and-config-server.md` §2 或 `web-managed-config.md`）补「哪份是权威」。

**P3（小问题）**：
1. `Status.vue` 新增 `class="peer-hostname-cell"` 但样式里无定义（空类）。
2. `connLossRate` 用 `conn.loss_rate ?? 0` → 字段缺失显示 `0%`，与 latency/jitter 的「拿不到就空」不一致（与实时表旧行为一致，可接受）。
3. `connPathQualityCell`/`connPathQualityTip` 与已有 `pathQualityCell`/`pathQualityTip` 格式串逻辑重复，改文案要改两处。
4. 配置模式下 `loadCurrentNetworkInfo()` 仍每 1s 一次 →「避免抢 RPC」只做了一半。
5. 新增的 pollTick / storage-first 路径无单测（`remote-management-config.spec.ts` 未改），但 Archive 文档把它列进了「测试」。
6. `get_jitter_us` 要求 `conn.stats` 存在，`get_loss_rate` 不要求 —— 小差异，不影响正确性。

### 结论

改动方向合理、前端实现干净、测试与类型检查全绿；但 **P1 必须先修**，否则「存储优先」在 Windows 上会连带打坏网卡名持久化。
