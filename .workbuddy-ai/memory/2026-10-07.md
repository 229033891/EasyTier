## 「UI 禁用网络后路由表/DNS 残留」排查与修复

### 结论（Windows）
- Windows 上**没有** Android 那种 VPN 服务：`tauri-plugin-vpnservice` 在桌面是空壳（`mobile` 模块、所有命令都 `#[cfg(mobile)]`，`init()` 不注册任何 command）。禁用网络只是让内核 `delete_network_instance` 掉那个实例。
- 残留的根因是 **wintun 适配器是持久设备**：rust-tun（`tun-easytier`，git 依赖）的 `Drop for Tun` 只做 `session.shutdown()`，不删适配器。所以会话结束后接口、IP、路由、DNS 注册表项都留在系统里，`route print` 仍能看到指向已失效接口的条目。
- DNS 残留：`system_config/windows.rs` 的 `WindowsDNSManager::close()` 原本是 `Ok(())` 空实现 → `NameServer=100.100.100.53` / `SearchList` / `EnableMulticast` 写进 TUN 适配器的 TCPIP 注册表键后从不回滚。工作区已（由前序改动）补上「只回滚自己写过的值」的逻辑。
- 另一个死代码陷阱：`virtual_nic.rs` 里 `run_proxy_cidrs_route_updater` 任务末尾的 `clear_underlay_exclude_routes` **实际永不执行** —— 该任务自己持有 `ArcGlobalCtx`（含 broadcast sender），`RecvError::Closed` 等不到，循环不会 break，最后 JoinSet drop 时被 abort。

最确定的 3 条（P0）：
1. **A1 `TauriVpnService.self` 只在 `onCreate` 赋值**（`TauriVpnService.kt:59`），而 `onRevoke()`（`:78`）会把它置 null；插件却把 `onRevoke()` 当内部 stop 用（`VpnServicePlugin.kt:101/129`）。服务实例仍存活时走一次 startVpn → `self` 永久为 null → 之后 `stopVpn` 的 `self?.onRevoke()` 变空操作 → `disconnect()` 因 `self != this` 既不 emit `vpn_service_stop` 也不关 PFD → 前端 `waitVpnStatus(false,3)` 超时抛错（`mobile_vpn.ts:338`）→ 被 catch 后继续 `doStartVpn`，而它开头 `if (curVpnStatus.running) return` 直接返回 → **UI 认为已连接、原生已死**。修法：`self = this` 移到 `onStartCommand`；内部停止与系统回调拆开；`disconnect()` 不要用 `self` 做守卫。
2. **A2 重复 `establish()` 不关旧 `vpnInterface`**（`TauriVpnService.kt:46`，`disconnect()` 只关当前字段）→ 泄漏 tun fd。
3. **A3 全部对账跑在 WebView JS 定时器里**（`mobile_vpn.ts:713-736` 的 10s sync + setTimeout 链），Rust 侧无 watchdog → App 退后台/Doze 时定时器被节流 → 孤儿 VPN / 配置变更 / 实例启停都不收敛，「有时候」卡住只能拉回前台。

其余 P1/P2：`START_STICKY` + null intent 用默认参数建孤儿 VPN（A4）；3s `waitVpnStatus` 无重试导致 owner 抖动（A5）；`set_tun_fd` 取「第一个」实例 + `try_send` 静默丢 fd（A6）；`NicCtx.close_notifier` **全仓无 await 点**，TUN 读流终止后无人恢复（A7）；`install_mobile_tun` 失败只 log（A8）；`drain()` 是异步 abort → fd 号复用可能让 `AsyncFd::new` 报 EEXIST（A10）；`mtu: 1300` 硬编码忽略 `config.mtu`（A11）；`addAddress("fd00::1",128)` 硬编码（A12）。

**⚠️ 最大的坑：`import/no-duplicates` 的 autofix 会改坏代码。**
`main.ts` 原本是
```ts
import { createRouter, createWebHistory } from 'vue-router/auto'
import { routes } from 'vue-router/auto-routes'
```
`--fix` 把两条合并成 `from 'vue-router/auto'`，直接丢掉 `routes` → `vue-tsc` 报 `'vue-router/auto' has no exported member named 'routes'`。原因：`vue-router/auto-routes` 是 unplugin-vue-router 的**虚拟模块**，ESLint 的 node resolver 把它解析到了和 `vue-router/auto` 同一个物理文件（`vue-router/dist/vue-router.mjs`），于是误判为重复导入。修法：还原两条 import + 在 `eslint.config.js` 对 `src/main.ts` 关闭该规则（附注释说明）。**结论：对依赖虚拟模块/别名解析的 import，不要盲信 `import/no-duplicates` 的 autofix，必须看 diff。**
