# 2026-10-07

## 「UI 禁用网络后路由表/DNS 残留」排查与修复

### 结论（Windows）
- Windows 上**没有** Android 那种 VPN 服务：`tauri-plugin-vpnservice` 在桌面是空壳（`mobile` 模块、所有命令都 `#[cfg(mobile)]`，`init()` 不注册任何 command）。禁用网络只是让内核 `delete_network_instance` 掉那个实例。
- 残留的根因是 **wintun 适配器是持久设备**：rust-tun（`tun-easytier`，git 依赖）的 `Drop for Tun` 只做 `session.shutdown()`，不删适配器。所以会话结束后接口、IP、路由、DNS 注册表项都留在系统里，`route print` 仍能看到指向已失效接口的条目。
- DNS 残留：`system_config/windows.rs` 的 `WindowsDNSManager::close()` 原本是 `Ok(())` 空实现 → `NameServer=100.100.100.53` / `SearchList` / `EnableMulticast` 写进 TUN 适配器的 TCPIP 注册表键后从不回滚。工作区已（由前序改动）补上「只回滚自己写过的值」的逻辑。
- 另一个死代码陷阱：`virtual_nic.rs` 里 `run_proxy_cidrs_route_updater` 任务末尾的 `clear_underlay_exclude_routes` **实际永不执行** —— 该任务自己持有 `ArcGlobalCtx`（含 broadcast sender），`RecvError::Closed` 等不到，循环不会 break，最后 JoinSet drop 时被 abort。

### 本次改动（未提交）
- `easytier/src/instance/runtime_host/tun_common.rs`：`remove_installed_proxy_cidr_routes` → 重命名并扩展为 `cleanup_tun_leftovers`，四步清理：
  1. 按 `proxy_cidr_route_sync().installed` 删本实例装过的 proxy CIDR / `/0`（**去掉了原来 `installed.is_empty()` 就 return 的早退** —— 普通组网没有 proxy CIDR，早退会导致整个清理变成空操作，这正是残留的主因之一）
  2. best-effort 删 TUN 上 `::/0`（循环 4 次，覆盖 exit + public-provider）
  3. Windows：`remove_ip/remove_ipv6(None)` 刷掉 TUN 适配器地址（连带清掉 on-link 子网路由）
  4. 新增 `cleanup_underlay_exclude_routes`：按 `underlay_exclude_ips()` + `find_*_physical_default()` 卸掉钉在物理网卡上的 `/32` `/128` 排除路由
- `tun_desktop.rs` / `tun_mobile.rs`：调用点改名。
- `docs/current/traffic-steering.md`：第 3 节补「停止时显式清理」条目。

### 已知残留风险（未处理）
- `revert_if_ours` 只在「当前注册表值 == 我们写过的值」时才回滚；`set_primary_dns` 在无 IPv4 nameserver 时仍会写 `EnableMulticast=0`，此时不会回滚。
- `disable_dynamic_updates` / `disable_netbios` 写的注册表项从不回滚（属持久适配器的常驻设置，可接受）。
- `MagicDnsServerInstance::new` 中途被 cancel 时，detached 的 `spawn_blocking(do_system_config)` 仍可能写 DNS，而 `clean_env` 因 `self.server` 还是 None 不会回滚（窗口很窄）。
- 适配器本身不会被删除，`et_*` 网卡会长期留在系统里（`reg_delete_obsoleted_items` 只清 NetworkList profile）。

### 第二轮补充改动
- `easytier-gui/src/composables/event.ts`：`onVpnServiceStop` 补 `type() === 'android'` 判断（桌面禁用最后一个网络时后端也会 emit 该事件，不加判断会去 invoke 桌面未注册的 `plugin:vpnservice|get_vpn_status`）。
- `easytier/src/instance/dns_server/system_config/windows.rs`：`revert_if_ours` 增加「expected 为空且注册表里没有 NameServer」也算自己的状态 —— 否则 `set_primary_dns` 无条件写的 `EnableMulticast=0` 永远回滚不掉。
- `easytier-web/frontend-lib/src/locales/en.yaml:122`：`logging_clear_partial` 的值含 `: ` 且未加引号，YAML 解析成嵌套 mapping，**直接让 `frontend-lib` 的 vite build 失败**。已加单引号（cn.yaml 用的是全角冒号，不受影响）。

### 新发现（未修，待决策）
Windows 上 `dev_name` 为空时（GUI 默认），`virtual_nic.rs::create_tun` 每次都用 `format!("et_{}_{}", interface_count(), 4位随机)` 生成**新**适配器名；而 `interface_count()` 是全机网卡数，会随新建适配器递增。GUI 保存配置发生在 TUN 创建之前，生成的 dev_name 不会写回 → **每次启用网络都会多一张 `et_*` 网卡**，旧网卡带着路由/IP/DNS 注册表项长期滞留。修法二选一：把生成的 dev_name 落盘，或改成按 instance_id 派生稳定名字（如 `et_{uuid前8位}`）。
