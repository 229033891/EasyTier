## git push 代理问题（已解决）
- 环境变量代理 127.0.0.1:63602 对 github CONNECT 返回 502；7897 端口代理本身可用（curl 测试 github 200）。
- 但 git 读环境变量代理仍 502，需显式 `git -c http.proxy=http://127.0.0.1:7897 push` 才成功。
- 结论：本机 push GitHub 用 `git -c http.proxy=http://127.0.0.1:7897 push origin dev`。

## 2026-11-04 opencode.ai 策略路由不通排查（DEV 节点 10.10.10.101）
- 现象：客户端配置 `[[policy_routes]]` domains=opencode.ai/github.com → peers=10.10.10.50 后 ping 不通；添加前直连是通的。
- 客户端侧全部正常：日志确认学到 172.65.90.20~23/32 并装入 OS 路由（metric 9005 → et TUN）；隧道到 10.10.10.50 健康（ping 28ms 0 丢包，边 rtt 1.8ms）。
- 关键证据：走隧道的 ICMP 与 TCP 全部超时；tracert 第一跳 10.10.10.50 应答后无第二跳 ⇒ 包到达 ubuntu 节点但未被转发。
- 结论（依据 docs/current/traffic-steering.md §5「规则=出口」/ §6）：policy_routes 命中的包带 exit_node 标志，对端必须开 enable_exit_node，否则丢包且不回退。最可能原因：10.10.10.50 未开启「允许成为出口节点」。
- 修复方向：在 ubuntu 节点开启 enable_exit_node 后重试；仍不通再查其版本过旧/防火墙。
- 顺带发现：本机 Ethernet0 DNS 含 172.21.0.1（docker 网关）且超时，另一独立小问题。

## 根因确认（opencode.ai 出口黑洞）
- trace 抓到 DEV→hk 的 SYN：flags=7（含 EXIT_NODE 位），包到达 hk 后被 "send packet to nic channel" 直接写入 TUN，代理引擎未触碰；`gateway::dataplane: data_plane_active=false`。
- 源码定位：`easytier-core/src/config/gateway.rs::ProxyRuntimeConfig::should_start`：`forward_by_system=true && !no_tun` 时**即使 enable_exit_node=true 也不启动用户态代理服务**（设计为交内核转发）。`forward_by_system ← flags.proxy_forward_by_system`（控制台「系统转发」勾选）。
- hk 控制台勾了「系统转发」，但其内核未开 ip_forward/NAT ⇒ 包进 TUN 后被内核丢弃。
- 修复：取消「系统转发」勾选（走用户态代理），或给内核配 ip_forward+MASQUERADE。
- 精查修正：hk 内核 ip_forward=1 已开、ufw FORWARD 策略 ACCEPT（不拦）。真正根因：**NAT 规则网段写错**——POSTROUTING 仅有 `-s 10.10.0.0/24` 的 MASQUERADE（OpenVPN tun0 网段），EasyTier 网段 10.10.10.0/24 无 NAT ⇒ 包以私网源 10.10.10.101 出 eth0 上公网，回程黑洞。
- 已修复并验证通过：`iptables -t nat -I POSTROUTING 1 -s 10.10.10.0/24 ! -d 10.10.10.0/24 -o eth0 -j MASQUERADE`，DEV ping opencode.ai 0% 丢失（32ms）。规则备份在 /root/iptables-backup-2026-11-04.rules。
- 待办（hk）：持久化尚未做——追加 nat 表块到 /etc/ufw/before.rules + `ufw reload`（重启会丢规则）；reload 后需核对 OpenVPN 的 FORWARD 放行（-s 10.10.0.0/24）未被冲掉。
- 【收尾】持久化已完成：nat 表块追加至 /etc/ufw/before.rules，`ufw reload` 无报错；OpenVPN 的 MASQUERADE（位置4）与 FORWARD 放行（规则2）均未被冲掉。仅剩清理：reload 后 POSTROUTING 出现重复的 EasyTier MASQUERADE（运行时手动条目 + before.rules 条目），删运行时那条即可。备份：/root/iptables-backup-2026-11-04.rules、/etc/ufw/before.rules.bak-2026-11-04。经验：hk 上 OpenVPN(10.10.0.0/24) 与 EasyTier(10.10.10.0/24) 两个 VPN 网段并存，内核 NAT 需分别覆盖；EasyTier「系统转发」模式完全依赖内核 iptables 路径。
