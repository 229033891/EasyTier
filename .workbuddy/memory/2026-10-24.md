## 修复实施：P1.5 最后一条路径 hold 改为「有界 + 仅限已 round-trip 的 conn」

改动文件：`easytier-core/src/peers/conn/peer_conn_ping.rs`（主）、`easytier/src/tests/three_node.rs`（注释/预算说明）、`docs/ops/ci-failure-log.md`（新增 2026-10-24 条目）、`docs/roadmap/stability-abc-plan.md`（§3.4 增加「宽限必须有限」验收项）。

- 删除 `LAST_PATH_FORCE_CLOSE_EXTRA`（按 miss 数宽限 +5 次），改为 `LAST_PATH_HOLD_MAX = 5s` 墙钟预算（自首次越过 `fail_close_count` 起算）。
- 新增 `had_roundtrip` 状态：从未 round-trip 成功的 conn 不享受 hold，到阈值即关（恢复 4aa7bb50 之前时序 —— 这是 credential/portal 用例被拖 10s 的直接原因）。
- 传输已死（`Err(Error::Tunnel(TunnelError::Shutdown))` 或 `close_notify.is_closed()`）→ 立即 break，不再空数 miss（`mpsc.rs` 里 Shutdown 只在 forward 任务退出/关闭后出现，可安全视为终态）。
- 宽限期 `ping fail close skipped` 日志 warn→debug（stability plan §3.4 要求）；新增 warn `last path hold expired, closing the connection`；原「too many consecutive pingpong failures」串保持不变（docs 有引用）。
- 新增单测 `never_round_tripped_conn_closes_even_when_gate_denies`（门禁恒 deny 也必须能关）。
- 环境坑：workspace 根目录/`target` 带 `Everyone:(CI)(DENY)(S,DC)` ACL，构建脚本无法在 target 内建/重命名临时文件（cc-rs "failed to create OUT_DIR"）。绕法：`CARGO_TARGET_DIR=D:/et-target cargo ...`。
- 验证：`cargo test -p easytier-core --lib peers::conn::peer_conn_ping` 11 passed；`cargo fmt --all --check` 通过；clippy 对本文件无告警（其余为既有 test cfg 告警）。集成用例需 Linux netns，本机 WSL 被禁，未能本地跑。

## 审查暂存改动（code review）：发现 3 个必修问题

### 必修 1：easytier-web 编译失败（E0277 ×3）
`easytier-web/src/restful/flow_history.rs` 的 `run_series` 返回类型被改成 `Vec<(i64, String, …)>`，但实际 `try_get::<String>("conn_id")` 返回 String，断言也是 `r.0 == "42"`（字符串比较）。
→ `cargo check -p easytier-web --tests` 报 3 个 E0277。**这正是 2026-10-23 那次 ET Test 红过的同一个坑**（commit 364915f3 修过一次），这次改动把它改回来了。返回类型第一项应保持 `String`。

### 必修 2：flow_history F-2 修复被回退（删掉了「未来行」上界）
本次改动删除了 `SERIES_SQL` / `PEER_HOSTNAME_SQL` 里的 `sampled_at <= ?` 上界，并删掉回归测试 `series_ignores_rows_dated_in_the_future`。
但 F-2 是 `eea68c4b` 专门修的缺陷（`docs/current/tunnel-ip-flow-fixes.md` §F-2 + §3.1 验收清单仍写着「两条 SQL 均含 sampled_at <= ?」）。删上界后：节点时钟超前的行会落进**每一次**查询窗口，把曲线整体抬高。
→ 要么恢复上界，要么在 fixes 文档里明确写「F-2 回退 + 理由」，不能既删代码又删测试又留着验收清单。

### 必修 3：Status.vue 用了不存在的 i18n 键
`status.flow_detail` 在 cn.yaml / en.yaml 里都不存在（新增的「流量明细」列表头），前端会直接显示原始 key 字符串。
另：`status.flow_panel*` / `status.flow_filter_*` / `status.flow_peer` 共 8 个键已随旧流量面板删除，变成孤儿键（`flowPanelFilter.ts` 模块与其 spec 也成孤儿，仅被测试引用）。
