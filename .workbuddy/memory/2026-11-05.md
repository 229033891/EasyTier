## 托盘「网络配置」清单改为一级菜单并置顶（用户决策：全扁平，分组信息可去掉）
- 决策背景：原实现是 `tray.ts::buildTrayConfigSubmenu()` 的二级菜单（混排 ●/○、上限 12）。用户要求全扁平 + 清单放根菜单最上方，并明确「分组信息去掉也可以接受」→ 标题/计数行一并删除，运行数只由托盘 tooltip 承载。
- 改动：`easytier-gui/src/composables/tray.ts` 去掉 `Submenu`（含 `setTrayMenu` 参数类型），`buildTrayConfigItems()` 返回菜单项数组，`buildTrayMenuItems()` 把清单放在最前面，随后才是「打开窗口」、service 5 行、「退出」（exit 恒末尾）。离线/空列表各只留一行 disabled 占位；`hidden > 0` 仍追加 `config-more`。`TrayConfigMenuLabels` 删除 `title` 字段。
- `tray_config_menu.ts`：`TRAY_CONFIG_MENU_MAX` 12 → 6（根菜单总行数受 Win32 弹出菜单高度限制），注释同步；`runningCount` 保留为模型字段但菜单不再用。
- 文案：`index.vue` 不再传 title；`cn.yaml`/`en.yaml` 删除 `tray.configs` 与 `tray.configs_title` 两个 key。
- 文档同步：`docs/current/desktop-gui-and-config-server.md` §1.1 新增「托盘菜单是全扁平的」条目 + 最近审阅日期；`docs/roadmap/tray-run-state.md` 关联段措辞。
- 新增 `easytier-gui/src/composables/tray_menu.test.ts`（mock `@tauri-apps/api/menu|path|tray|window`）断言：清单置顶、无 Submenu、exit 末尾、●/○ 前缀与点击路由、截断提示、离线/空占位、无清单时的兜底菜单。
- 验证：`pnpm lint` (eslint 全量) 通过、`vue-tsc --noEmit` 通过、`npx vitest run --maxWorkers=1 --minWorkers=1` 7 文件 82 测试全通过、两份 locale YAML 用 js-yaml 解析且 tray 键一致。**注意**：多 worker 并行跑 vitest 在本沙箱会触发 `EPERM ... Temp/.../ssr/` 写缓存报错（环境限制，非代码问题），用单 worker 规避。
- 已知取舍（已写进文档）：根菜单顺序随「运行中优先」排序变化；单击即触发启停（启动对已运行实例 = 拆 WinTun 重建，靠 `trayConfigActionIsNoop` 事前挡掉）；`setTrayMenu()` 仍靠 `trayConfigMenuKey` 避免 30s 轮询无谓重建。**未做真机验收**（Win11 托盘展开高度、Linux AppIndicator 下 disabled 占位行渲染）。

- 逐行复核后**未发现功能性错误**：`buildTrayConfigItems` 三个分支都至少产出 1 行（不会出现顶部孤立 separator）；`hidden>0` 只在 `entries>0 && ready` 时可能；`trayConfigMenuKey` 覆盖全量 entries，配置增减会触发 `config-more` 重建；`clientRunning=false` → `lastTrayListing=undefined` → `ready=false` 链路仍成立。

- 交叉校验：GUI 中 18 个 `t('tray.*')` 键在中英 YAML 均存在、键集合一致；唯一未被 `t()` 引用的 `tray.show` 是 76b6522d 遗留的死键（`generateMenuItem()` 用硬编码英文 `'Show / Hide'`），与本次改动无关。

- `easytier-gui/dist/` 里仍有 10-31 的旧 bundle（含旧 `tray.configs_title` 代码），已被 gitignore；直接跑旧构建产物会看到旧菜单，需重新构建。

## Windows NSIS 安装器「adding … to PATH failed (code 1)」根因与修复
- 现象：2.7.10 GUI 安装弹该 MessageBox；实测本机 Machine PATH 已含 `C:\Program Files\ET`、`where ET-cli` 正常 ⇒ 弹窗是**误报**，不要按提示重复执行 `SetEnvironmentVariable`（会追加重复项）。
- 根因：86e2c5d0 的 `ET_WritePathHelperScript` 在 `FileWrite` 里写了 PowerShell 转义 `` `r`n ``，而 NSIS 字符串换行必须是 `$\r$\n`（同文件 MessageBox 用的就是对的）。生成的临时 `.ps1` 是一整行夹字面 `` `r`n ``，`powershell -File` 解析失败退出 1（报错落在 `foreach ($scope in …)` 附近）；卸载用的 remove helper 同样坏掉。
- 验证：本机 `%LOCALAPPDATA%\tauri\NSIS\makensis.exe` 编译同一宏做对照，完整 add helper 修复前 exit 1、修复后 exit 0；从**真实源码**抽取宏编译探针得 `add=0 remove=0`，生成的脚本恢复成 37/27 行正常多行。
- 改动：`easytier-gui/src-tauri/windows/installer-hooks.nsh`（52 处换行转义、补根因注释 3、em dash 改 ASCII）、`docs/ops/windows-build-pack.md`（补 E 行/验证说明/误报提示）、新增 `easytier-gui/src-tauri/windows/verify-path-hook-nsis.ps1`（编译真实宏 + 断言 add/remove exit 0，add 指向已在 PATH 的目录、remove 指向不存在的目录 ⇒ 零 PATH 副作用，已 PASS）。
- 教训：`prove-path-hook.ps1` 只测 PowerShell 层，必须编译 NSIS 并看 `nsExec` 退出码才能验收 `FileWrite` 产物。**未重新打包 NSIS 安装包前，安装仍会弹此框**；本机 PATH 无需任何操作。
