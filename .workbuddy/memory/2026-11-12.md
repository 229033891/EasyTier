## 续 3（14:23）：根因确认 = `enable_quic_proxy = true`

## 续 4（14:35）：判定「域名出口不支持 QUIC 代理」并在保存配置时加提示

- 用户需求：检查域名出口能否支持 QUIC 代理，能就加支持，不能就在保存配置时提示。
- **判定：不支持，且不宜顺手加**。源码依据：
  - `connect_wrapped_transport_source()`（`wrapped_transport/packet_plane.rs:76-98`）用 `get_peer_id_by_ipv4_allowing_default_proxy(公网IP)` 找承载 peer；`peer_ospf_route.rs:1034` 的 default-proxy 分支严格要求 `cidr.network_length() == 0`（peer 通告的 /0 learned route）。
  - `[[policy_routes]] domains` 是本机 L2/L3 策略：只把 MagicDNS 观测学到的 /32 装进 OS 路由表，effective gateway peer 留在 L3 policy 快照，**不写 peer OSPF 路由表**（`cidr_monitor.rs:893` 明确本地 /0 是 local declaration、不是 learned route）。故公网 IP 必然查不到 → `no peer found for wrapped TCP dst` → connect Err → RST。
  - `real_dst_ip_for_mode(QuicSrc) => Some(origin_ip)` 无条件放行（`tcp_proxy_engine.rs:576`），所以不是准入拒绝，而是缺选路信息；`check_packet_from_peer_fast(QuicSrc) => true`。
  - destination 端 `wrapped_transport_destination.rs:293` 用原生 socket 连公网目标**可行** ⇒ 理论能做，但要把 L3 effective peer 注入 `WrappedTransportSourceConnector`（跨 gateway/proxy ↔ peers/route ↔ config），`route/mod.rs:219-221` 还明确禁止把 allow-default-proxy 用于 L3 出站路由；另需对端 `disable_quic_input=false` + QUIC endpoint prepared + ACL Forward，且现有测试对 QUIC+域名出口零覆盖 ⇒ 架构级改动，非开关级。
  - QUIC 代理语义是「发往虚拟网内对端的 TCP 流」，公网域名出口超出设计范围；帮助文案承诺的「自动回退原始 TCP」在本场景也没兑现。
- 实现（UI-only warn，不阻止保存、不改写值，遵循 `configConflicts.ts` 现有约定）：
  - `frontend-lib/src/modules/configConflicts.ts` 新增 `quic_proxy_domain_egress`（warn），条件 = `enable_quic_proxy && policy_routes 有 domains 且 peers 非空`。只针对域名出口，避免对内网 CIDR / exit_nodes 误报（后者可能产生 /0 让 QUIC 反而正常）。
  - `locales/cn.yaml`、`en.yaml` 新增 `quic_proxy_domain_egress_conflict_help`，并在 `enable_quic_proxy_help` 补一句限制。
  - `components/RemoteManagement.vue` 新增 `warnTrafficBreakingConflicts(cfg)`，在 `saveAndRunNewNetwork`（Run）与 `doSaveNetworkConfig`（Save）入口弹 warn toast —— Web 纳管路径 `hideRunButton=true`，Config.vue 内置按钮不渲染，必须在这里补。
  - `tests/config-conflicts.spec.ts` 加 3 个用例（命中 / QUIC 关不报 / 纯 CIDR 或无 peers 不报）。Config.vue 的常驻冲突 banner 自动带上新警告。
- 验证：`pnpm test:config-ui` 32 文件 278 用例全过；`pnpm exec vue-tsc -b` 通过；`pnpm exec vite build` 通过；`cargo fmt --all -- --check` 通过。
